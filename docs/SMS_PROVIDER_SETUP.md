# HOME-E-FIX: 2Factor & Indian DLT SMS Provider Setup Manual

This document details the configuration for **2Factor.in**, the initial real Indian SMS delivery provider, along with the TRAI DLT regulatory requirements.

---

## 1. 2Factor.in Account & API Credentials

1. Register or log in at [2Factor.in](https://2factor.in/).
2. Navigate to **API Keys** in the dashboard.
3. Generate or copy your primary **API Key**.
4. Configure the API Key in Supabase Secrets / Cloudflare Worker Secrets:
   ```bash
   TWOFACTOR_API_KEY="your-api-key"
   ```

---

## 2. TRAI DLT Compliance Requirements (India)

Under Telecom Regulatory Authority of India (TRAI) regulations, all commercial and transactional SMS messages dispatched to Indian mobile numbers (+91) must comply with DLT (Distributed Ledger Technology):

### A. Principal Entity (PE) Registration
- Register Home-e-Fix as an Enterprise / Principal Entity on any telecom operator DLT portal (e.g., Jio, Airtel, Vodafone Idea, BSNL).
- Obtain your **Entity ID**.

### B. Header / Sender ID Registration
- Register a 6-character alphabetic Header (e.g., `HEFFIX` or `HOMEFX`) under the **Transactional / Service Implicit** category.
- Map this Header in your 2Factor.in dashboard.

### C. Content Template Registration
Register your OTP content template. Example:
```text
Your Home-e-Fix verification OTP is {#var#}. Valid for 5 minutes. Do not share this code with anyone. - Home-e-Fix
```
- Once approved by the telecom operator, copy the **Template ID** (or Template Name).
- Set `TWOFACTOR_TEMPLATE_ID` in your backend secrets.

## 3. Official 2Factor Custom OTP Contract

The Home-e-Fix adapter uses 2Factor's official Custom OTP REST endpoint:

```http
GET https://2factor.in/API/V1/:api_key/SMS/:phone_number/:otp_value/:otp_template_name
```

- `:api_key`: Your 2Factor API key.
- `:phone_number`: 10-digit Indian mobile number.
- `:otp_value`: 6-digit OTP code generated by Supabase Auth.
- `:otp_template_name`: Approved DLT template name.

### Successful Response:
```json
{
  "Status": "Success",
  "Details": "9c1a5b8f-3d2e-4b6a-8f1a-9c1a5b8f3d2e"
}
```

### Error Response:
```json
{
  "Status": "Error",
  "Details": "INVALID_API_KEY"
}
```

## 4. Provider-Independent Architecture

The SMS layer is built on the `SmsProvider` interface (`sendOtp({ phone, otp, purpose, locale })`).  
To switch to another Indian carrier (e.g. SpringEdge) in the future:
1. Implement `SpringEdgeSmsProvider` implementing `SmsProvider`.
2. Update the factory in `otpService.ts` to instantiate `SpringEdgeSmsProvider` when `SMS_PROVIDER=springedge`.
3. **Zero changes** are needed in Customer Auth, Professional Registration, Turnstile, or Booking workflows.
